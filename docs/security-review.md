**Security and data-integrity findings, ordered by priority**

| Priority | Finding and impact | Evidence and recommended change |
| --- | --- | --- |
| High | Attachment previews can disclose the bearer token to an external host. An absolute attachment URL is accepted unchanged, while image and video widgets attach the session token without checking its destination. | `lib/core/utils/attachment_url.dart:47,120`, `lib/shared/widgets/app_note_tile.dart:150`, and other media widgets. Reproduction confirms an external URL is accepted and the synthetic token header is supplied; the widget joins these values. Require approved HTTPS origins before attaching credentials, and check redirect behavior for every media transport. |
| High | An old account's in-flight note response or failed save can populate the new account's cache or upload queue. | `lib/features/note/data/repositories/note_sync_repository.dart:40,58,144`: account keys are evaluated from the current session after asynchronous work. Reproductions show account A's note arriving in B's cache and A's private title entering B's queue. The folder repository has the same mutable-owner pattern. Capture owner and session revision at operation start, reject stale completions, and keep every queue replay bound to its originating account. Transport revision checks alone do not protect repository persistence. |
| High | The shared `unknown` owner fallback exposes cached notes to other accounts and can adopt another owner's queued work. | `note_sync_repository.dart:934,950`, `folder_sync_repository.dart:453,465` under their respective repository directories. The unknown-cache disclosure is reproduced. Require a stable owner ID and remove cross-owner fallback; migrate legacy data only with verified ownership. |
| High | Profile information is shared between accounts on the same installation. Names, phone numbers, family information, email, and avatar references use global keys. | `lib/core/storage/profile_extras_storage.dart:16` and `lib/features/profile/presentation/controllers/profile_controller.dart:104,136,143`. Shared storage survives an account switch in the reproduction; the controller prefers the previous local name and phone over the new API user's values. Scope profile extras and media by account, migrate deliberately, and reload them when ownership changes. |
| High | A completed sync can silently erase a newer offline edit. | `lib/features/note/data/repositories/note_sync_repository.dart:438,537,542`. A flusher takes a snapshot, waits for network work, then replaces the current queue and cache. A reproduction adds a second note while the first is syncing; completion removes the second note from both the queue and cache. Serialize flushes and mutations, and acknowledge individual operations without overwriting later edits. Folder queue replacement needs the same review. |
| High | Account deletion can report success when the server returns HTTP 200 with `success: false`; it also leaves local private data behind. | `lib/features/auth/data/datasources/auth_remote_data_source.dart:257` ignores the response envelope. `lib/features/auth/data/repositories/auth_repository_impl.dart:103` then clears only the session. The reproduction confirms a rejected deletion is reported as successful while an identity storage key and cached note remain. Validate explicit server success, then erase the deleted account's notes, queues, documents, photos, and profile extras. Keep logout retention policy separate from permanent deletion. |
| High | Deleting the last national ID also deletes saved passports and their managed images. | `lib/core/storage/id_information_storage.dart:272,279,308`. The last-ID branch deletes the entire shared document snapshot and image directory. Reproduced with one ID plus a separate passport. Delete only the selected document and its unreferenced images, preserving other document types. |
| High | Sensitive notes, sync queues, profile extras, and identity/passport photos have no app-level encryption at rest. | Signed-in and guest notes use GetStorage JSON; daily notes and profile extras do too. Identity metadata uses FlutterSecureStorage, but `lib/core/storage/app_media_storage.dart:35` copies original image bytes into documents storage. Encrypt sensitive records and media with authenticated encryption and protected keys. OS sandbox and device encryption provide useful protection, but do not establish app-level encryption or E2EE. This matches the risk described by [OWASP's private-storage guidance](https://mas.owasp.org/MASWE-0001/). |
| High | “Lock note” does not enforce an authentication boundary. | `lib/features/note/presentation/controllers/note_detail_controller.dart:3249` toggles a Boolean. `lib/routes/note_navigation.dart:9` opens the note without authentication; content remains available to previews and search. Add authentication and content protection across open, search, preview, share, and export paths before presenting this as a security feature. |
| Medium | E2EE labels and initialization readiness exceed the implemented protection. | Notes are serialized directly into JSON requests in `lib/features/note/data/datasources/note_remote_data_source.dart:151`; the encryption service only generates/uploads keys. Identity UI displays `E2EE-AES`, “End-to-End Encrypted,” and chip-signature validation text without the corresponding document encryption/verification flow. `encryption_service.dart:45` skips uploads when private keys exist, even after an earlier upload failed; `:72` discards the generated signature, and `userId` is unused for key scoping. Remove unsupported claims or implement and validate the protocol. Track per-account upload acknowledgment separately from local key existence. |
| Medium | Explicit signature/issuer/audience rejection leaves the rejected session locally signed in. | `lib/core/network/api_client.dart:146` deliberately skips invalidation for these challenges. Two existing session-recovery tests fail on that behavior. Sync repositories also treat unauthorized responses as offline success. Resolve the intended behavior, update the README accordingly, and distinguish failed authorization from loss of connectivity. This finding does not imply the backend accepts invalid tokens. |
| Medium | Sensitive Android files have no explicit backup exclusions. | `android/app/src/main/AndroidManifest.xml:16` sets no backup policy or extraction rules. Android defaults can include app files in backup. Define exclusions for sensitive records and media and test cloud backup and device transfer; inspect the merged release manifest. See [Android Auto Backup documentation](https://developer.android.com/identity/data/autobackup). |

**Completeness and release blockers**

| Area | Remaining work |
| --- | --- |
| Passport-only storage | `IdInformationStorage.savePassport` can create a snapshot without `profile` or `card`. `read` and `readCards` assume those fields exist and throw `TypeError`. Reproduced after saving the first passport. Make each document type independently readable and test passport-first, mixed-document, and deletion cases. |
| Android builds | Allow debug configuration without release signing credentials. Keep release signing mandatory for release builds. The release configuration also references an absent `android/app/proguard-rules.pro`; resolve and verify that configuration. |
| Android BlinkID compatibility | The project pins AGP 8.12.1 and Kotlin 2.2.20. The pinned BlinkID 8001 package documents AGP 9.1.0+ and Kotlin 2.2.21+. Reconcile the complete Gradle toolchain and verify min SDK/native plugins with a full build, following the [publisher's requirements](https://pub.dev/packages/blinkid_flutter/versions/8001.0.0). |
| iOS builds | Diagnose the empty Swift package target and verify a clean simulator build. A simulator result does not replace a signed archive or device testing. |
| Android versioning | Gradle hardcodes version code 2 and version name 1.0.0 while `pubspec.yaml` is 1.0.2+24. Use the intended Flutter build version and verify store upgrade behavior. |
| Google authentication | Checked-in iOS client IDs are blank. Android requires a supplied `GOOGLE_SERVER_CLIENT_ID`. Default configuration cannot complete Google sign-in or Google password recovery. Configure release OAuth credentials and platform registrations, then test on devices. |
| Profile synchronization | Profile edits remain local in `ProfileRepositoryImpl`. They do not update the server or synchronize across installations. Establish the supported server contract before presenting cloud profile editing as complete. |
| Server OCR fallback | `AppConstants.identityApiUrl` is explicitly proposed and unconfirmed. The fallback attempts `/api/identity/scan`; local OCR does not validate this endpoint. Confirm its contract and privacy behavior before relying on it. |
| Trash and archive | `ApiCapabilities.permanentDelete` is false; signed-in permanent note/folder deletion and empty trash are unsupported. Bulk unarchive in `archive_view.dart:281` only shows a “coming soon” message. |
| Payment-card persistence | Cards are held in the controller's memory and disappear after restart/controller disposal. The model retains CVV in memory. Define the intended card-storage lifecycle and minimize retained security-code data; do not equate the “saved” screen with durable persistence. |

**Failures in the captured full test run**

- `document_upload_test.dart`: multipart retry after session refresh. Its fake session does not increment revisions during `saveSession`, although production retry checks require that increment; fix the fixture and verify the actual multipart retry before concluding it is a transport defect.
- `session_recovery_test.dart`: signature rejection without replay; concurrent/repeated signature rejection. The implementation currently preserves the rejected session, conflicting with the assertions and documented behavior.
- `card_flow_ui_test.dart`: manual entry/CVV/save/add-another flow. A required widget is not found.
- `empty_to_added_test.dart`: adding the first card through the UI. A required widget is not found.
- `identity_scan_test.dart`: immediate front download/back added later; printable export; image-tap/full-image viewer; selected card details on profile; complete Khmer API details. Some export assertions still expect PDF while the controller now produces PNG, and several finders/field expectations do not match the current UI. Distinguish stale assertions from behavior regressions and restore meaningful passing coverage.

**Existing protections worth retaining**

Access and refresh tokens use platform secure storage. The default APIs use HTTPS. The Dio interceptor limits bearer injection to configured service origins and guards stale retries, and session persistence serializes writes. Password-reset tokens remain in screen memory. Debug authentication diagnostics avoid printing whole bearer tokens. These protections do not cover the independent media-header helper or repository ownership races described above.

**Recommended order:** fix token destination checks and all account isolation paths first; repair concurrent sync and document deletion next; implement real note protection and encrypted storage; validate account deletion; resolve mobile builds and restore passing tests; then perform device and backend checks.

Backend implementation and a signed-in test account were not available. Server ownership enforcement, OTP/reset rate limits and expiry, token revocation, successful live login/upload/deletion, server-side encryption, and backup/retention were not verified. Physical-device camera/OCR, permission handling, background/resume behavior, and signed store builds remain unverified. A repository review and clean dependency-advisory result cannot certify those systems as secure.
